# 交互式菜单系统（Menu System）

> v1: 5行×2列 二级菜单 | 节点图 ID 1073742447 | 文件 `src/menu_system.ts`

## 架构概览

```
按钮输入（角色实体）        渲染输出（关卡实体 stage）
┌──────────┐              ┌──────────────────┐
│ 上 1073742328 │          │ stage._menu_fld1 │ ← 第一列前缀（* 或 空格）
│ 下 1073742329 │  导航     │ stage._menu_fld2 │ ← 第一列内容（不变）
│ 左 1073742330 │ ─────→   │ stage._menu_fld3 │ ← 第二列前缀
│ 右 1073742331 │  状态机   │ stage._menu_fld4 │ ← 第二列内容（随子菜单变）
│ 空格1073742335│          └──────────────────┘
└──────────┘                    ↓
                          文本框渲染（struct 菜单）
                    字段1[i]+字段2[i] = "*运行控制"
                    字段3[i]+字段4[i] = " 单步完整"
```

## 挂载规则（重要）

- 节点图 **必须挂载到角色实体** — `界面控件组触发时` 只有触发交互的玩家节点图能收到
- 多人防重复：`evt.eventSourceEntity != self` 时直接 return

## 渲染模板

### 方案 A：独立变量（当前使用，直接可用）

4 个 str_list 变量直接渲染，无需额外编辑器配置：

```
{1:lv._menu_fld1.0} {1:lv._menu_fld2.0} · {1:lv._menu_fld3.0} {1:lv._menu_fld4.0}
{1:lv._menu_fld1.1} {1:lv._menu_fld2.1} · {1:lv._menu_fld3.1} {1:lv._menu_fld4.1}
{1:lv._menu_fld1.2} {1:lv._menu_fld2.2} · {1:lv._menu_fld3.2} {1:lv._menu_fld4.2}
{1:lv._menu_fld1.3} {1:lv._menu_fld2.3} · {1:lv._menu_fld3.3} {1:lv._menu_fld4.3}
{1:lv._menu_fld1.4} {1:lv._menu_fld2.4} · {1:lv._menu_fld3.4} {1:lv._menu_fld4.4}
```

- `lv` = 关卡实体（stage）
- `_menu_fld1~4` = 4 个独立的 str_list 自定义变量
- `·` = 列分隔符（装饰用）

### 方案 B：struct 包装（需要编辑器额外配置）

在编辑器中建 struct `菜单`（4 个字段 `1,2,3,4`），每个字段引用方案 A 的变量。渲染模板更简洁：

```
{1:lv.菜单.1.0} {1:lv.菜单.2.0} · {1:lv.菜单.3.0} {1:lv.菜单.4.0}
{1:lv.菜单.1.1} {1:lv.菜单.2.1} · {1:lv.菜单.3.1} {1:lv.菜单.4.1}
{1:lv.菜单.1.2} {1:lv.菜单.2.2} · {1:lv.菜单.3.2} {1:lv.菜单.4.2}
{1:lv.菜单.1.3} {1:lv.菜单.2.3} · {1:lv.菜单.3.3} {1:lv.菜单.4.3}
{1:lv.菜单.1.4} {1:lv.菜单.2.4} · {1:lv.菜单.3.4} {1:lv.菜单.4.4}
```

- `菜单` = struct 变量名
- `.1.0` = 字段1的第0个元素

> genshin-ts TypeScript 无法直接写 struct，代码写独立变量。方案 B 只是包一层壳让模板更好看。**当前使用方案 A**。

### 换用别的变量

将模板中的 `_menu_fld` 替换为你的变量名前缀即可。

## 数据流

1. 用户按按钮 → `界面控件组触发时` → 多人守卫 → 读 `_menuRow/_menuCol/_menuMainIdx`
2. 更新状态变量（导航逻辑）
3. 构建 4 个 `list('str', [5])` → 写入 `stage._menu_fld1~4`
4. 文本框刷新（方案A直接读变量，方案B通过struct间接读）

## 状态变量（在 self 即角色实体上，float 类型）

| 变量 | 含义 | 范围 |
|------|------|------|
| `_menuRow` | 当前行 | 0 ~ maxRow（取决于列） |
| `_menuCol` | 当前列 | 0=主菜单, 1=子菜单 |
| `_menuMainIdx` | 当前主菜单索引 | 0~3 |
| `_menuScrollOffset`（v2） | 滚动偏移 | 0..N（预留） |

## 渲染变量（在 stage 上，str_list 类型，长度 5）

| 变量 | 列 | 类型 | struct 字段 | 说明 |
|------|-----|------|-------------|------|
| `_menu_fld1` | 1 | 前缀 | 菜单.1 | `*` = 选中，` ` = 未选中 |
| `_menu_fld2` | 1 | 内容 | 菜单.2 | 主菜单文本，编译期定义 |
| `_menu_fld3` | 2 | 前缀 | 菜单.3 | `*` = 选中，` ` = 未选中 |
| `_menu_fld4` | 2 | 内容 | 菜单.4 | 子菜单文本，运行时按 mainIdx 切换 |

## 菜单内容（v1：调试面板）

| 主菜单 | 子菜单 |
|--------|--------|
| 运行控制 | 单步完整 / 恢复运行 / 慢速切换 |
| 状态跳转 | 强制静止 / 强制滚动 / 强制滑动 / 强制空中 / 强制锁定 |
| 信息诊断 | 打印诊断 / 守卫评估 |
| 其他操作 | 重置足球 / 单步转移 / 单步物理 |

## 如何为新系统接入

1. 复制 `src/menu_system.ts`
2. 修改内容配置区：
   - `COL1` → 新的主菜单项
   - `SUB_0` ~ `SUB_3` → 新的子菜单项
   - `SUB_*_COUNT` → 子菜单项数
3. 替换命令执行段的逻辑
4. 分配新的节点图 ID
5. 在编辑器中配置新的 struct 变量和文本框模板

## v2 扩展预留

| 特性 | 当前（v1） | v2 设计 |
|------|-----------|---------|
| 行数 | 固定 5（`VISIBLE_ROWS = 5`） | 动态变量 + 滚动偏移 `_menuScrollOffset` |
| 列数 | 固定 2（`MENU_MAX_DEPTH = 2`） | 路径栈 `_menuPath[]` |
| 菜单层级 | 二级 | 多级（路径栈 push/pop） |
| 命令绑定 | 硬编码 if-else | 可注册回调表 |
| 滚动 | 不支持 | 数据项数 > VISIBLE_ROWS 时上下键轮询 |
| 挂载 | 角色实体 | 同 |
